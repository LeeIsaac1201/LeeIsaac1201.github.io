HomeHero

A service marketplace platform connecting homeowners with local, vetted service providers, built for CP2 Capstone Project.

role: solo UI/UX design context: capstone (supervised) tools: HTML/CSS, PHP/MySQL status: alpha prototype
// 01 — overview

Project overview

Goals

HomeHero acts as an intermediary connecting homeowners who need home services with local service providers. It's a two-sided marketplace, so finding a trustworthy provider (or picking up a side income opportunity) doesn't have to rely on word-of-mouth or informal channels.

Target audience & context

Two user groups: homeowners searching for and booking service providers, and providers looking for a side or primary income stream. It's currently an alpha prototype scoped to Malaysia, a deliberate constraint given this was built within a single capstone semester, not intended as a production-ready launch.

// 02 — process

Design process

Reconstructed from the decisions made throughout the build, since this project was developed iteratively alongside the code rather than fully designed upfront.

01

Research

Competitor analysis of existing home-service platforms, focused on identifying friction points homeowners and providers face with informal, fragmented booking processes.

02

Ideation

Used AI tools to help explore an initial feature set, reflecting my interest in AI-assisted workflows, then narrowed it down to what was realistic for a single-semester scope.

03

Wireframing

No separate wireframing stage. I designed directly in HTML/CSS, using the browser itself as the wireframing surface rather than working through Figma first.

04

Prototyping

The build functions as both prototype and foundation: as an alpha version, it validates the core flows now while laying the groundwork for a future production version.

05

Testing

Had friends use the live application and gave informal feedback, which surfaced issues to address before treating it as stable.

// 04 — decisions

Key design decision & trade-off

I originally planned a full admin role, a dashboard for moderating listings and approving providers, but scrapped it under time constraints.

Instead of building a dedicated admin interface, I made peace with handling admin-level changes directly through phpMyAdmin for now. It's not a decision I'd defend for a production platform. There's no audit trail, no safeguards against a bad edit, and it doesn't scale past one person managing the system. But for an alpha prototype with a single-semester deadline, it let me protect the features homeowners and providers actually touch, rather than spending scarce time on tooling only I would use. It's an explicit item for future work rather than something I consider solved.

// 05 — challenges & results

Challenges and outcomes

Challenges

The main challenge was making sure everything worked as intended within a limited timeframe. Balancing feature scope against a single-semester deadline meant constant prioritization, and accepting that some features (like the admin role above) had to be cut rather than compromised on.

Results

No formal grade or supervisor feedback yet. The next thing I'd build is a proper admin role: a dashboard for approving new service provider registrations, moderating listings and reviews, and resolving disputes between homeowners and providers, instead of relying on direct database access as a stand-in.
